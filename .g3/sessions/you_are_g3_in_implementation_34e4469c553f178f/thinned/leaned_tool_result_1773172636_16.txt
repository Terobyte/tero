## Архитектура для цели 100%: "Не сдаёмся до победы"

```
ApplicationPipeline:
│
├─ Level 1: DOM Automation (быстро, бесплатно)
│   ├── SelectorEngine 4-tier
│   ├── AnswerBank + FormPatternStore
│   └── Verified click loop (проверяем состояние после каждой стратегии)
│       → ~70% заявок проходят тут
│
├─ Level 2: AI-Assisted (умеренно, дёшево)
│   ├── AIAnswerer chain (Gemini → DeepSeek → Kimi)
│   ├── AI coordinate click (bounding boxes)
│   └── Fuzzy select matching
│       → ещё ~20% заявок
│
├─ Level 3: AI-Full Control (медленно, дороже)
│   ├── Screenshot → "заполни всю форму" → action list
│   ├── Form backtracking (другой вариант ответа)
│   └── Multi-attempt на уровне шага
│       → ещё ~8% заявок
│
├─ Level 4: HITL (ручной, последний resort)
│   ├── Telegram alert: screenshot + кнопки "помочь" / "пропустить"
│   └── Retry через N часов (CAPTCHA могла уйти)
│       → оставшиеся ~2%
│
└─ RetryScheduler (поверх всех уровней):
    ├── Network/timeout → retry 1/5/15 мин
    ├── Rate limit → retry 1 час
    ├── Site down → retry 6 часов
    └── Permanent (already_applied, expired) → mark, не retry
```

## Phase -1 — Retry Architecture (КРИТИЧЕСКИ ВАЖНО, ДЕЛАТЬ ПЕРВЫМ)

**Проблема:** В codebase нет retry вообще. `grep -r "retry\|max_retries" src/applier/` — ноль результатов.
Одна сетевая ошибка = заявка навсегда в статусе "error". Без retry 100% недостижимо.

**Новый класс `RetryPolicy` в `queue_manager.py`:**
```python
class RetryPolicy:
    MAX_RETRIES = 3
    BACKOFF_SECONDS = [60, 300, 900]  # 1 мин, 5 мин, 15 мин

    RETRYABLE = {
        "network_error", "timeout", "stale_element",
        "rate_limited", "captcha", "page_crash", "unknown_error"
    }
    NON_RETRYABLE = {
        "already_applied", "job_expired", "not_eligible",
        "missing_required_field"  # нет смысла повторять — нужен HITL
    }

    @classmethod
    def should_retry(cls, error_type: str, attempt: int) -> bool:
        return error_type in cls.RETRYABLE and attempt < cls.MAX_RETRIES

    @classmethod
    def delay_seconds(cls, attempt: int) -> int:
        return cls.BACKOFF_SECONDS[min(attempt, len(cls.BACKOFF_SECONDS) - 1)]
```

**Схема в БД:** добавить поля `retry_count`, `retry_after`, `last_error_type` в таблицу заявок.

### Правильная верификация состояния (три метода, не один)

**Проблема оригинального плана:** `is_checked()` работает только для `<input type="checkbox">`.
Для `<div role="checkbox">` (Indeed, Workday) — бросает exception.

```python
async def verify_element_state(element, should_check: bool) -> bool | None:
    """
    Верифицировать состояние элемента тремя способами.
    Возвращает True/False если верифицировано, None если неизвестно.
    """
    # Метод 1: нативный (input[type=checkbox])
    try:
        return await element.is_checked() == should_check
    except Exception:
        pass

    # Метод 2: aria-checked (div[role=checkbox/radio])
    try:
        aria = await element.get_attribute("aria-checked")
        if aria is not None:
            return (aria == "true") == should_check
    except Exception:
        pass

    # Метод 3: CSS-классы ("checked", "selected", "active", "on")
    try:
        classes = await element.get_attribute("class") or ""
        has_checked = any(w in classes.lower() for w in ["checked", "selected", "active", "-on"])
        return has_checked == should_check
    except Exception:
        pass

    return None  # не удалось верифицировать — идти дальше


async def fill_checkbox_verified(element, answer: str) -> bool:
    should_check = answer.lower() in ["yes", "true", "1"]

    # Уже в нужном состоянии?
    state = await verify_element_state(element, should_check)
    if state is True:
        return True

    strategies = [
        ("label_js",      _strategy_label_js),
        ("label_pw",      _strategy_label_pw),
        ("direct_click",  _strategy_direct_click),
        ("force_click",   _strategy_force_click),
        ("js_click",      _strategy_js_click),
        ("set_property",  _strategy_set_property),
    ]

    for name, strategy in strategies:
        try:
            await strategy(element, should_check)
        except Exception:
            continue

        await asyncio.sleep(0.15)  # дать DOM обновиться

        verified = await verify_element_state(element, should_check)
        if verified is True:
            # Запомнить для StrategyStore (Phase 1)
            return True
        elif verified is False:
            continue
        # verified is None → неизвестно, считаем успехом и идём дальше
        # (лучше чем зависнуть)

    logger.warning("⚠️ fill_checkbox_verified: all 6 passes — state unverified")
    return False
```

> **ВАЖНО: НЕ использовать `el.setAttribute('aria-checked', 'true')` без настоящего клика** —
> это фальсификация. React/Angular не увидят изменение, сервер получит старое значение.
> Pass 3 текущего кода (строка 49-57) содержит эту ошибку — удалить.

### `fill_select()` — полный рефакторинг (Phase 0.6)

```python
async def fill_select(element, answer: str, page=None) -> bool:
    """
    Заполнить <select>. Возвращает bool (сейчас возвращает None — BUG).
    Стратегии: exact → case-insensitive → substring → fuzzy → AI
    """
    options = await element.locator("option").all_text_contents()
    best = _fuzzy_match(answer, options, threshold=0.65)

    if best:
        try:
            await element.select_option(label=best)
            actual = await element.input_value()
            return actual != ""
        except Exception:
            pass

    # AI fallback: дать список опций + вопрос → LLM выбирает
    if page:
        chosen = await ai_choose_option(answer, options, page)
        if chosen:
            await element.select_option(label=chosen)
            return True

    logger.warning(f"⚠️ fill_select: no match for '{answer}' in {options[:5]}...")
    return False
```

## Phase 2 — AI Fallback Chain (Gemini → Kimi 2.5 → DeepSeek)

**Ожидаемый impact: 0% → ~80% на элементах где DOM вообще не работает**

> **ИСПРАВЛЕНИЕ по сравнению с исходным планом:**
> Не использовать self-reported `"confidence"` от LLM — это бесполезная метрика.
> LLM не знает своей точности. Вместо этого — **верифицировать результат применения**.

Новый файл: `src/ai/llm_chain.py`

```python
AI_FALLBACK_CHAIN = [
    {"provider": "gemini",     "model": "gemini-2.0-flash",              "key": "GEMINI_API_KEY"},
    {"provider": "blackboxai", "model": "kimi-2.5",                      "key": "BLACKBOX_API_KEY"},
    {"provider": "openrouter", "model": "deepseek/deepseek-chat-v3:free", "key": "OPENROUTER_API_KEY"},
]

async def call_chain_verified(page, screenshot: bytes, prompt: str,
                               verify_fn=None) -> dict | None:
    """
    Пробует каждый LLM до первого верифицированного результата.
    verify_fn(page, result) -> bool: применить результат и проверить.
    """
    for provider in AI_FALLBACK_CHAIN:
        try:
            result = await _call_provider(provider, screenshot, prompt)
            if not result:
                continue

            if verify_fn:
                success = await verify_fn(page, result)
                if success:
                    return result
            else:
                return result  # без верификации — вернуть первый непустой результат

        except (RateLimitError, TimeoutError, APIError):
            continue
    return None
```

Интеграция:
- `fill_checkbox_verified()` / `click_radio_option()` → после 6 DOM-стратегий → `ai_click_fallback()`
- `SelectorEngine._llm_discover()` → заменить single Gemini call на `call_chain_verified()`
- `AIAnswerer` → fallback на Kimi когда Gemini rate-limited

## Phase 4 — Form Backtracking FSM (НОВОЕ)

**Проблема:** Нет механизма "попробовать другой ответ". Если AnswerBank дал "3 years" но
поле ожидает одно из {"1-2", "3-5", "5+"} — форма не сабмитится, нет отката.

```python
class FormStateMachine:
    """FSM с откатом: если шаг не проходит — откатить и попробовать другие ответы."""

    async def fill_step(self, step, questions: list[Question]) -> bool:
        for attempt in range(3):
            snapshot = await self.save_dom_state()  # сохранить заполненные значения

            answer_variant = await self._get_answer_variant(questions, attempt)
            success = await self._try_fill(questions, answer_variant)

            if success and await self._can_advance():
                return True

            await self.restore_dom_state(snapshot)  # откатить
            logger.info(f"↩️ FSM: rollback step, attempt {attempt+1}")

        return False  # все варианты исчерпаны → Level 3 AI Full Form Mode

    async def _get_answer_variant(self, questions, attempt: int):
        """attempt=0: AnswerBank. attempt=1: AIAnswerer. attempt=2: aggressive defaults."""
```

## Phase 8 — Full Form AI Mode (когда всё сломалось)

**Последний resort Level 3:** если на шаге формы ≥3 элемента провалились через DOM:

```python
async def ai_fill_entire_step(page, questions: list[Question]) -> bool:
    screenshot = await page.screenshot()
    prompt = f"""Заполни форму на скриншоте. Вопросы и ответы:
    {json.dumps([{"q": q.text, "a": q.answer} for q in questions])}
    Верни JSON: [{{"x": int, "y": int, "action": "click"|"type", "value": str}}]"""

    actions = await call_chain_verified(page, screenshot, prompt)
    for action in actions:
        if action["action"] == "click":
            await page.mouse.click(action["x"], action["y"])
        elif action["action"] == "type":
            await page.mouse.click(action["x"], action["y"])
            await page.keyboard.type(action["value"])
    return True
```

## Phase 9 — HITL: Telegram Escape Valve (НОВОЕ)

**Последний resort Level 4:** когда AI тоже не справился или форма требует живого человека.

```python
async def request_human_help(page, job: Job, reason: str) -> bool:
    screenshot = await page.screenshot()
    msg = (
        f"🆘 *Нужна помощь!*\n"
        f"Вакансия: {job.title} @ {job.company}\n"
        f"Причина: {reason}\n"
        f"Бюджет заявки исчерпан или форма нечитаема.\n\n"
        f"[Помочь вручную] — открыть браузер\n"
        f"[Пропустить] — эта вакансия не важна"
    )
    await telegram.send_photo(screenshot, caption=msg, buttons=["Помочь", "Пропустить"])
    # Ждать ответа пользователя или таймаут 30 мин
    response = await telegram.wait_response(timeout=1800)
    return response == "Помочь"
```

## Идеи из статьи (browser-use / DeepSeek)

### AOM вместо DOM-парсинга (Phase 5)
browser-use выбросил `buildDomTree.js` и перешёл на **Accessibility Object Model (AOM)**:
- Уже отфильтровывает невидимые элементы
- Содержит семантические роли, labels, описания
- Стабилен к MTD-ротации CSS-классов

### Stochastic delays — более реалистичная модель
Роботы детектируются по **математическим следам**:
- Гауссовское распределение (уже есть) +
- Редкие длинные «thinking pauses» (2-10 сек) +
- Иногда «возврат назад» (scroll up, re-read)

### URL-parameter injection для фильтров
Когда UI-фильтр скрыт — инжектировать параметры напрямую в URL
(`f_WT=2` для LinkedIn Remote). Стабильнее чем кликать по UI-чекбоксу.

## Anti-detection обновления

| Параметр | Текущее состояние | Рекомендация |
|---------|------------------|--------------|
| Browser mode | storage_state (cookies) | CDP port 9222 к живому браузеру (Phase 6) |
| Delays | Gaussian(min, max) | Gaussian + редкие thinking паузы + backtrack |
| Daily limits | WarmupTracker 5→10→max | + случайные 5-10 мин перерывы внутри дня |
| Session | Новый контекст каждый раз | Переиспользовать сессию внутри одного дня |
| IP | Без прокси | Residential proxy (опционально) |
| Activity hours | ScheduleGuard 9-18 | + случайные 5-10 мин перерывы внутри дня |

### Критическое: никогда не делать
- Запускать 24/7 (палево — живые люди спят)
- Менять IP резко (город A → город B за секунды)
- Одинаковые тексты сообщений (semantic hashing на LinkedIn)
- `incognito` браузер без истории cookies

## Принцип: "AI always available" + "Never give up"

**Правило 1:** на каждом уровне взаимодействия должен быть AI fallback.

| Уровень | DOM-автоматика | AI Fallback | Кэш |
|---------|---------------|-------------|------|
| Найти элемент | SelectorEngine Tier 1-3 | Tier 4 LLM Vision | SelectorCache |
| Кликнуть/заполнить | 6 стратегий клика | AI coordinate click | StrategyStore |
| Ответить на вопрос | AnswerBank + паттерны | Gemini/Kimi generation | CustomAnswers |
| Навигация (iframe, next step) | URL/DOM patterns | AI screenshot analysis | FormPatternStore |
| Вся форма целиком | Шаг-за-шагом | AI Full Form Mode | FormPatternStore |

**Правило 2:** если что-то упало — retry, не fail.

| Тип ошибки | Действие |
|------------|----------|
| Network / timeout | Retry через 1/5/15 мин |
| Rate limit | Retry через 1 час |
| Stale element | Re-locate + retry немедленно |
| Wrong answer → form reject | Backtracking FSM + другой ответ |
| Бюджет API исчерпан | HITL Telegram |
| Site полностью broken | Retry через 6 часов |
| Already applied | Permanent fail, не retry |

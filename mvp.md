# MVP Ladder — G3 Coach-Player

> Шкала от 1 до 10.
> `1` = работает и можно потрогать руками.
> `10` = система которая улучшает сама себя и превосходит любой одиночный агент.
>
> **Главная метрика на каждом уровне: среднее количество багов в результате.**
> Меньше багов = система умнее.

---

## Как читать эту шкалу

| Диапазон | Что это |
|---|---|
| 1-3 | Локальный прототип, работает у тебя на машине |
| 4-6 | Рабочий инструмент для ежедневного использования |
| 7-8 | Продукт который не стыдно показать |
| 9-10 | Мировой уровень, недостижимый для копирования |

---

## Уровень 1 — Доказательство идеи

### Вопрос на который отвечает этот уровень
> "Схема `2 агента → 1 судья → лучший результат` — она вообще работает?"

### Что обязательно есть

- `ccg` и `ccg2` как две отдельные команды с разными аккаунтами
- Запуск одного duel на одно ТЗ
- Два изолированных workspace (git worktree или copy)
- Bug Detection Pipeline: тесты + линтер + типы
- Один judge, выбирает `winner_a` или `winner_b`
- Запись run record в `runs.jsonl` (даже без анализа)
- Базовый вывод в терминал: кто победил, сколько багов

### Чего нет

- Resume
- Panel judge
- Synthesis
- Красивый UI
- Рекомендации конфигурации

### Критерий готовности

```
Запустил g3 go --plan req.md
Оба агента отработали параллельно
Judge выбрал одного
В runs.jsonl появилась запись
Видно сколько багов у каждого
```

### Метрика уровня
Первые прогоны. Данных мало. Главное — что это работает.

## Уровень 2 — Можно пользоваться самому

### Вопрос
> "Могу ли я использовать это каждый день не сходя с ума?"

### Что добавляем

- Resume после сбоя (state machine + write-ahead)
- Human feedback после каждого прогона: approve/reject/skip
- Запись feedback в `runs.jsonl`
- Таймауты и корректное завершение зависших агентов
- `selection=best` и `selection=manual`
- `g3 insights` — базовая статистика: сколько прогонов, средний bug score

### Критерий готовности

```
Сессия не теряется от первого сбоя
Можно продолжить с точки остановки
После 5 прогонов g3 insights показывает первые цифры
```

### Метрика уровня
5+ прогонов. Система уже учится.

## Уровень 3 — Инструмент который становится умнее

### Вопрос
> "Через 2 недели использования — система хоть что-то поняла про мою работу?"

### Что добавляем

- Pre-run recommendations (после 5+ прогонов)
- Классификация задачи: type + complexity из текста ТЗ
- `g3 insights --agent-pairs` — кто с кем работает лучше
- Calibration весов (после 20+ прогонов с feedback)
- Artifact diff view: показать diff победителя в терминале
- `g3 inspect SESSION_ID` — детали прошлой сессии
- Retry policy: повтор при падении одного агента

### Критерий готовности

```
После 20 прогонов:
- система предлагает правильный agent pair для типа задачи
- среднее bug_score победителей ≤ 1.5
- approve rate ≥ 75%
```

### Метрика уровня
**Avg bug score ≤ 1.5** на рекомендованных конфигурациях.

### Вопрос
> "Могут ли другие люди пользоваться этим без меня рядом?"

### Что добавляем

- Panel judge mode (`--judge-mode panel`)
- Synthesis (`selection=synthesize`)
- Профили провайдеров через config.yaml
- Presets: `g3 go --preset thorough`
- Автоочистка старых worktree
- История и фильтрация: `g3 history --last 20`
- Human overrides в knowledge base: "никогда не использовать X на задачах типа Y"
- Более понятный terminal UI с прогресс-барами

### Критерий готовности

```
Другой человек установил систему, настроил два аккаунта
и дошёл до первого рабочего duel без помощи автора.
```

### Метрика уровня
**Avg bug score ≤ 1.0** при использовании рекомендованных конфигураций.

## Уровень 9 — Self-Improving System

### Вопрос
> "Может ли система улучшать саму себя?"

### Что добавляем

**`g3 self-improve` mode:**

1. User пишет ТЗ для улучшения G3
2. G3 запускает duel: два агента работают над кодом G3
3. Bug Detection прогоняет тесты самого G3
4. Judge выбирает лучшую версию G3
5. Human approve → promote
6. G3 перезапускается с новым кодом

**Safeguards:**
- Тесты G3 должны проходить после каждого self-improvement
- Human approve обязателен (нельзя авто-промоут)
- Backup текущего кода перед promote
- Coverage не может упасть ниже 80%

**Learning о self-improvement:**
- Какие агенты лучше улучшают G3?
- Какие типы улучшений работают хорошо?
- Накапливаем историю версий G3

### Критерий готовности

```
G3 успешно применяет свой пайплайн к своему коду.
Тесты G3 после self-improvement проходят.
Human approve возможен из стандартного интерфейса.
```

### Метрика уровня
После 10 self-improvement циклов: **avg bug score G3 улучшается**, а не ухудшается.

## Уровень 10 — World-Class

### Вопрос
> "Это уже категория сама по себе, а не просто инструмент?"

### Что это может включать

- Multi-tenant: командные workspace, shared knowledge base
- Marketplace провайдеров и judge-стратегий
- Benchmark framework на реальных задачах
- Multi-agent tournaments: best-of-N, а не только best-of-2
- Cross-project memory: паттерны работают на новых проектах
- Cost/quality optimizer в реальном времени
- Hybrid local/cloud execution
- API + webhooks для интеграции в CI/CD
- Automatic task decomposition: большая задача → несколько duel

### Метрика уровня
Система **предсказывает approve/reject** с точностью ≥ 85% до запуска,
и **сама предлагает конфигурацию которая даст 0 багов** для 80%+ задач.

## Рекомендуемый маршрут

```
Сейчас:  1 → 2 → 3  (первые месяц-два)
Потом:   4 → 5      (когда инструмент стал нужен другим)
Продукт: 6 → 8      (если цель — делать из этого бизнес)
Далее:   9 → 10     (если цель — превзойти всех)
```

**Самое важное правило:**

> Не переходи на следующий уровень пока текущий не работает стабильно.
> Уровень 3 с надёжной learning-системой лучше чем уровень 5 с нестабильной.

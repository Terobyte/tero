# tero-пульт 2: HUD на телефоне и живой хозяин

Дата: 2026-10-29. Версия: 0.1. Статус: черновик на одобрение.

Продолжение [спека пульта](2026-10-21-tero-pult-design.md) и [спека HUD](2026-10-22-tero-hud-design.md). Оба сделаны (планы 07 и 08 сданы, ветка `tero/all`).

## Зачем

План 08 дал пульт: tero не умирает молча, вопрос доходит до телефона, ответ доходит до прогона. Но после него осталась боль, которую Темирлан описал так: «один из прогонов просто остановился, я хз как его продолжить, а поговорить с агентом не могу, хз, жив ли он вообще».

Что именно не так сейчас, по коду:

- **Жив ли агент-хозяин, не видно нигде.** Файл `lease` в папке прогона хранит pid и срок аренды, `pid_alive` есть, но `tero status` печатает «аренда: null» как константу (`src/commands/runs.py`), в `status_payload` аренды нет, в белом списке полей ретранслятора (`relay/src/filter.js`, `STATE_FIELDS`) её тоже нет. HUD и телефон не могут сказать «агент мёртв 12 минут».
- **Нового агента никто не поднимает.** `wake_command` по умолчанию пустая. Умер агент — tero ждёт таймауты и уходит в автопилот. Команды «разбуди сейчас» нет ни в CLI, ни на пульте.
- **Остановленный прогон продолжает `tero resume`**, но ни статус, ни пульт не говорят «прогон остановлен, следующий шаг такой». С телефона `resume` не сделать.
- **До живого агента не достучаться.** Телефон доходит до агента только ответом на открытый вопрос. Написать ему «посмотри фазу 3, там не то» посреди работы нельзя.
- **На телефоне логи в пушах, а на маке красивый HUD.** Страница пульта это голый HTML без стилей, HUD на маке (ветка `hud-ux`) это карточка с лампочкой, фазами, цветным логом и бегущей строкой. Спек HUD обещал, что «вёрстка HUD потом переезжает на телефонную страницу». Пора.
- **Сам хозяин в HUD не виден.** Видно игрока, судью, тестера, гейт. Что делает Claude Code над ними, не видно ни на маке, ни на телефоне.

Хотим: с телефона видеть то же, что на маке, видеть, жив ли хозяин, будить его, продолжать прогон и писать хозяину, не открывая терминал. Всё это без нативного приложения и без shell на телефоне.

## Цели

1. **Агент виден.** `tero status`, HUD и телефон показывают одно: агент жив / умер N мин назад / агента не было, и какой хозяин (Claude Code, opencode, Muse).
2. **Телефон = HUD.** Страница пульта показывает ту же карточку, что HUD на маке: лампочка, фазы точками, модель цветом роли, лог со свечением по ролям, плашка «кто и что делает», план по тапу. Одна вёрстка, два источника данных.
3. **С телефона можно поднять прогон.** Действия `wake` (новый агент-хозяин) и `resume` (продолжить остановленный прогон), даже если на машине не осталось ни tero, ни агента.
4. **С телефона можно написать хозяину** в любой момент, не только в ответ на вопрос. Сообщение будит спящего агента и попадает к нему, а не в промпт игрока.
5. **Хозяин в логе.** Текст и вызовы инструментов Claude Code видны в HUD и на телефоне как ещё одна роль «хозяин», своим цветом, через тот же фильтр секретов.
6. **Одна модель представления** для CLI, HUD и ретранслятора вместо трёх расходящихся проекций `state.json`.

## Не цели (сейчас)

- Нативное приложение, Live Activity, кнопки в пуше: как и раньше, без Apple Developer.
- Терминал в браузере (ttyd, xterm.js за Cloudflare Tunnel): это shell на телефоне, см. анти-цели.
- Полноценный двусторонний чат с произвольным агентом. Сообщения хозяину идут через inbox tero, не через API хозяина.
- Транскрипт opencode и Muse в логе. Сначала Claude Code; остальные хозяева после замера, где они хранят сессию.
- Параллельные прогоны на одной машине, сквозное шифрование: как в спеке пульта.
- Android, виджет с кнопками.

## Анти-цели (провал, даже если «работает»)

- Телефон или ретранслятор могут выполнить произвольную команду на машине. Набор действий фиксированный; текст сообщения это текст, а не команда; команда пробуждения берётся только из локального конфига.
- Рядом с живым агентом запускается второй. `wake` при живой аренде отказывает.
- Транскрипт хозяина уносит в ретранслятор код, диффы, ключи или содержимое файлов. Тот же фильтр, что для ролей, плюс лимит длины строки.
- Агент тратит токены на опрос. Сообщение будит агента ровно один раз, через выход `tero wait`.
- Лампочка показывает «работает», когда tero или агент мертвы, или «машина на связи», когда сторож мёртв.
- Вёрстка на маке и на телефоне расходятся: две копии HTML с разными правками.
- Страница пульта без сети или без токена показывает пустоту вместо «нет связи» / «не привязан».

## Как это устроено

```
 хозяин-агент (Claude Code)              машина с tero
   │ tero go --detach ───────────────▶ tero-владелец: state.json, stream.jsonl, lease, pulse
   │ tero wait (фоном) ◀──────────────  коды 0/2/3/4/5/6 + новый 7 «сообщение хозяина»
   │ tero inbox / answer / resume       ответы и сообщения ← inbox/ ← опрос ретранслятора
   │                                    хвост транскрипта хозяина → stream.jsonl (роль host)
   │
   └─ tero watch (сторож, launchd) ───▶ опрос команд машины раз в 30 с: wake, resume
                                          │ только исходящие запросы
                                          ▼
                         ретранслятор (Cloudflare Worker + D1)
                         состояние (= модель HUD) · вопросы · ответы · сообщения · команды · пуши
                                          ▲
                        телефон: страница-пульт = карточка HUD + действия
```

### 1. Аренда агента наружу

Файл `lease` расширяется: `{until, pid, host, session, written_at}`. `host` это `claude` / `opencode` / `muse` / `""`, `session` это id сессии хозяина, если он его знает (см. п. 5). Пишет его `tero wait` и `tero answer`, как сейчас, плюс `tero wake`.

`status_payload` получает поле `agent`:

```
agent: {state: "alive" | "dead" | "none", host, pid, since_s, until_s}
```

- `alive`: аренда не истекла и pid жив.
- `dead`: аренда есть, pid мёртв или аренда истекла. `since_s` считается от `min(until, момент, когда pid перестал отвечать)`; точный момент смерти не известен, поэтому владелец при каждом пульсе проверяет pid и пишет `died_at` в `lease`, когда впервые видит его мёртвым.
- `none`: файла `lease` нет.

`tero status` печатает «агент: жив · claude · 12 мин до истечения» вместо «аренда: null». Поле `agent` входит в белый список ретранслятора (без `pid`, он на телефоне не нужен).

HUD: лампочка в `src/hud/model.py` (`_light`) учитывает агента. Статус `waiting_agent` или `judge_pending` при `agent.state != alive` это жёлтый с текстом «агента нет»; `stopped` при живом агенте остаётся красным, но плашка внизу говорит «хозяин жив, ждёт тебя» вместо голой причины. Трей показывает то же.

### 2. Сторож `tero watch`

Проблема: когда прогон `stopped` и агент умер, на машине не остаётся процесса, который опрашивает ретранслятор. Кнопка «продолжить» на телефоне нажимается в пустоту. Машина не принимает входящих, значит, нужен свой опрос.

`tero watch` это один процесс на машину под `flock` (`~/.tero/watch.lock`), ставится в launchd (`tero watch --install` пишет plist в `~/Library/LaunchAgents`, `--uninstall` убирает). Делает три вещи:

- Раз в 30 с спрашивает у ретранслятора команды машины: `GET /commands?machine_id=…` с ключом записи. Команды это `wake` и `resume` с `run_id`. Каждую исполняет один раз и подтверждает `POST /commands/ack`.
- Раз в 5 мин шлёт пульс машины `POST /machine` (время, версия tero, есть ли сторож). Страница показывает кнопки `wake`/`resume` только при свежем пульсе машины, иначе «машина не на связи» и кнопки серые.
- Если `tero go --detach` запущен без установленного сторожа, в консоль одна строка «сторожа нет: `tero watch --install`, иначе с телефона прогон не поднять». Без сторожа всё остальное работает как раньше.

Исполнение команд:

- `resume <run_id>`: только если статус прогона `stopped` или владелец мёртв, иначе отказ «прогон идёт». Запуск `tero resume --run <run_id>` через `detach_go`, как `go --detach`. Ответ с телефона на открытый вопрос, если он был, применяется при возобновлении, как в спеке пульта.
- `wake <run_id>`: см. п. 3.

Сторож исполняет только эти два слова. Текст команд в ретрансляторе не содержит путей и аргументов shell: `run_id` проверяется по регулярке имени папки прогона, как `_is_safe_uuid` для inbox.

### 3. `tero wake` и действие `wake`

`tero wake [--run <run>] [--force]` запускает `wake_command` из конфига сейчас, а не по истечению таймаутов:

- Аренда валидна и pid жив → отказ, код 1, «агент жив, pid N, до истечения M мин; `--force`, если точно надо». С телефона `--force` недоступен.
- Иначе `maybe_wake` с маркером `manual-<минута>` вместо `question_id`, не чаще раза в 5 мин на прогон. Запуск даёт аренду на `agent_timeout`, как сейчас.
- `wake_command` пустая → код 1 с подсказкой ниже.

**Дефолт `wake_command`.** Новое поле конфига `host: claude | opencode | muse | ""`. При `host: claude` и пустой `wake_command` tero подставляет команду из гайда для хозяев (`src/commands/guide_cmds.py`): `claude -p --permission-mode acceptEdits "Ты мозг tero. Выполни: tero guide; tero status --json --run {run_dir}; …"`. `tero go --detach` при пустом `host` угадывает по `TERO_AGENT_PID`: если родитель называется `claude`, пишет `host: claude` в `state.json` прогона (не в конфиг). Для opencode и Muse команды из гайда, они там помечены «не замерено», так и остаётся.

Промпт пробуждения получает причину: `{reason}` это `question` / `message` / `manual` / `stopped`. При `stopped` это «прогон остановлен: <причина>; `tero resume` или спроси хозяина». Так «открыть новый терминал Claude» с телефона это `wake` без вопроса: свежий headless-агент без старого контекста, как и описано в спеке пульта. Интерактивное окно терминала с телефона не открывается, это не цель.

На маке в HUD кнопок по дизайну нет. «Разбудить хозяина» и «продолжить прогон» это пункты меню трея по правому клику и контекстного меню лампочки, они зовут `tero wake` / `tero resume --detach` тем же путём.

### 4. Сообщение хозяину

- **Ретранслятор.** `POST /answer` принимает `action: "message"` без `question_id`, текст до 2000 символов, только с токена PWA (как текстовые ответы; `phone_text_answers: false` выключает и это). Хранится в той же таблице ответов с `question_id = ""`.
- **Владелец tero** опрашивает `/answers` не только в `waiting_*`, а во всех незавершённых статусах: раз в 10 с в ожидании, раз в 30 с во время шага. Сообщение кладётся в `inbox/msg-<uuid>` и подтверждается `ack`; в `state.json` растёт `messages_pending`. Сообщение **не** попадает в промпт игрока и ни на что в прогоне не влияет. Оно для хозяина.
- **`tero wait`** выходит с новым кодом **7** «сообщение хозяина», когда `messages_pending > 0` и статус не терминальный. Приоритет кодов: 0/4/2 (конец) > 3 (вопрос) > 7 (сообщение) > 5 > 6. Агент читает `tero inbox` (новая команда: список непрочитанных сообщений с временем, `--ack` помечает прочитанными), делает что хочет, и снова `tero wait`. Токены тратятся один раз на сообщение.
- **Агент спит, но аренды нет** (умер): владелец зовёт `maybe_wake` с `reason=message`, текст сообщения в промпт пробуждения в размеченном блоке, как ответы с телефона. Если `wake_command` пустая, сообщение ждёт в inbox, страница показывает «агента нет, сообщение ждёт».
- **Прогон `stopped`, владельца нет.** Сообщение остаётся в D1; сторож при `wake`/`resume` не читает сообщения, их заберёт владелец после возобновления. Страница так и пишет: «прогон остановлен, сообщение дойдёт после resume или wake».
- Гайд для хозяев (`tero guide`) получает абзац про код 7 и `tero inbox`.

### 5. Хозяин в логе

Claude Code пишет транскрипт сессии в `~/.claude/projects/<путь-к-репо-с-дефисами>/<session_id>.jsonl`: по строке на сообщение, с `type` (`user` / `assistant`), `cwd`, `sessionId`, текстом и `tool_use`.

- **Какая сессия.** Хозяин передаёт id сам: `tero wait --session <id>` или переменная `TERO_HOST_SESSION`; tero пишет его в `lease.session`. Если id не передан, владелец ищет в папке проекта самый свежий `.jsonl` с `cwd` равным репо, изменённый после старта прогона. Нашёл два свежих за минуту → не угадывает, роль `host` в логе молчит, `tero status` пишет «сессия хозяина: не определена». Это спайк первой фазы плана: проверить, что Claude Code 2.x действительно так хранит транскрипт и что `sessionId` есть в каждой строке.
- **Что берётся.** Из `assistant`: текстовые блоки до 300 символов и имена инструментов с первым аргументом (путь файла, команда до 120 символов). Из `user`: ничего, кроме пометки «хозяин получил ответ инструмента» не нужно, пропускаем. Результаты инструментов, содержимое файлов, диффы не берутся вообще.
- **Куда.** В `stream.jsonl` как события с `role: "host"`, типы `text` / `tool`, через `scrub_secrets` до записи. Хвост читается тем же офсетным ридером, что `Tail` у HUD, раз в 2 с, только пока аренда жива.
- **HUD.** Роль «хозяин» получает свой цвет (бирюзовый, остальные четыре заняты) в логе, плашке и `ROLE_NAMES`. Лампочка от хозяина не зависит: он не роль прогона. На телефоне эти же строки приходят в `events`; на странице есть переключатель «только хозяин» и поле сообщения прямо под логом. Это и есть «вкладка Claude Code»: не вкладка, а фильтр и поле ввода.
- **Ретранслятор.** `events` уже в белом списке; роль `host` проходит через тот же фильтр (`filter.js`), лимит 300 символов на строку остаётся. Пути файлов идут как сейчас: относительные, секретные только именем.

### 6. Одна модель представления

Сейчас три проекции `state.json`: `status_payload` (CLI), `build_view` (HUD), `push_state` (ретранслятор). Они уже разошлись: аренда есть только в файле, `light` есть только в HUD.

- `build_view` (`src/hud/model.py`) становится единственной. Вход: `state`, хвост `stream.jsonl`, `lease`, `pulse`, `now`. Выход: словарь, который HUD рисует как есть.
- `status_payload` = `build_view` + поля, нужные только CLI (пути, `relay_error`). `tero status --json` отдаёт то же, что видит HUD.
- `push_state` отправляет `build_view` целиком через фильтр; белый список `STATE_FIELDS` дополняется полями модели: `light`, `light_text`, `sectors`, `role_line`, `doing`, `verdict`, `verdict_age_s`, `agent`, `done_text`, `stop_text`, `debt_line`, `phase_title`. Частота отправки как сейчас (при изменении снимка плюс пульс), не чаще раза в 5 с, чтобы хвост лога не бил по лимиту записей D1.
- **Страница пульта это тот же `view.html`.** Файл один, в `src/hud/view.html`; при деплое ретранслятора `tero relay setup` кладёт его копию в `relay/public/hud.html` (копия генерируется, в git только исходник; тест сверяет, что копия не отстала). Источник данных абстрагируется: `window.teroSource.view()` возвращает промис с моделью. На маке это мост pywebview, на телефоне это `fetch('/state')` раз в 15 с. Действия (`toggle_visible`, `save_size`, `switch`) на телефоне отсутствуют, страница их не показывает.
- На телефоне под карточкой HUD остаётся то, чего на маке нет: вопрос с кнопками и полем, действия `wake` / `resume` / `message`, «уже отвечено», лимиты, привязка и пуши. Порядок на странице: открытый вопрос первым (как в спеке пульта), затем карточка, затем остальное.

### 7. Что видно на странице при каждом состоянии

| Состояние | Лампочка | Плашка | Доступно |
|---|---|---|---|
| прогон идёт, агент жив | зелёная | роль и строка | message |
| вопрос, ждёт тебя | жёлтая «вопрос» | текст вопроса | ответ, message |
| вопрос, агента нет | жёлтая «агента нет» | «агент умер 12 мин назад» | ответ, wake, message |
| stopped, агент жив | красная «стоп» | причина + «хозяин жив» | message, resume |
| stopped, агента нет | красная «стоп» | причина + «агента нет» | resume, wake |
| машина не на связи | серая «нет связи» | время последнего пульса | ничего, пояснение |
| done | зелёная ✓ | итог | ничего |

## Порядок

1. **Аренда наружу.** `lease` с `host` / `session` / `died_at`, `agent` в `status_payload` и белом списке, лампочка и плашка в HUD, трей. Полдня, снимает «хз, жив ли он».
2. **Одна модель и карточка на телефоне.** `build_view` как единственная проекция, копия `view.html` в `relay/public`, `teroSource`, страница с карточкой сверху. Критерий: скриншоты HUD на маке и страницы на телефоне по одному `state.json` совпадают по содержанию.
3. **Сообщение хозяину.** `/answer` с `message`, опрос во всех статусах, `inbox/msg-*`, код 7, `tero inbox`, гайд.
4. **Сторож, `wake`, `resume`.** `tero wake`, `host` в конфиге и дефолт `wake_command`, `tero watch` с launchd, `/commands`, `/machine`, кнопки на странице по таблице п. 7, меню трея.
5. **Хозяин в логе.** Спайк по транскрипту Claude Code, `--session`, хвост в `stream.jsonl`, цвет и фильтр.

Каждый пункт полезен сам по себе и сдаётся отдельной фазой плана.

## Решения, которые принял я (Claude), не Темирлан

- Сторож как отдельный процесс под launchd, а не «владелец живёт вечно»: владелец умирает вместе с прогоном по дизайну плана 08, менять это дороже и опаснее (двойники).
- Сторож исполняет только `wake` и `resume`, команда пробуждения только из локального конфига; текст с телефона никогда не становится аргументом команды.
- `wake` при живой аренде отказывает; `--force` только из терминала.
- Сообщение хозяину это код выхода `wait`, а не `claude -p --resume <id>` снаружи: второй процесс на той же сессии рядом с живым интерактивным это непроверенный путь, а код выхода уже работает. `--resume` остаётся запасным путём в гайде.
- Сообщение не попадает в промпт игрока. Телефон и так может писать игроку через ответ на вопрос; смешивать каналы опасно (анти-цель «текст с телефона переписывает правила»).
- Код 7 ниже 3 по приоритету: вопрос важнее сообщения.
- Одна вёрстка с копией при деплое, а не два файла: правки на маке автоматически доезжают до телефона.
- `build_view` как единственная модель, CLI и ретранслятор берут её, а не наоборот: она самая богатая и покрыта тестами.
- Хозяин в логе только через файл транскрипта, без хуков Claude Code: хуки требуют правки `~/.claude/settings.json` у каждого хозяина, файл есть всегда.
- Из транскрипта берётся только текст ассистента и имена инструментов, результаты инструментов никогда: там содержимое файлов.
- Цвет хозяина бирюзовый, роль в логе называется «хозяин».
- Пульс машины 5 мин, опрос команд 30 с: 2880 запросов в сутки, бесплатный Worker это выдерживает.
- Отправка модели в ретранслятор не чаще раза в 5 с.

## Оставлено строителю

- Схема таблиц `commands` и `machines` в D1, точные маршруты и коды ошибок.
- Как `view.html` переключает источник: один `<script>`-шим в копии или флаг в самом файле.
- Формат plist для launchd и поведение сторожа при обновлении tero (перезапуск).
- Как именно `tero go --detach` узнаёт имя родительского процесса (psutil уже есть).
- Регулярка для имени роли `host` в фильтре и цвет в CSS.
- Тесты: аренда (жив / умер / нет / died_at), приоритет кодов `wait`, опрос в разных статусах, отказ `wake` при живой аренде, лимит частоты `wake`, сторож под flock с фейковым ретранслятором, `resume` только для `stopped`, сверка копии `view.html`, скриншотный тест страницы на фейковом `state.json`, хвост транскрипта на фейковом `.jsonl` с секретом внутри.

## Приёмка

1. `kill -9` агента-хозяина посреди ожидания вопроса: через минуту `tero status`, HUD и страница показывают «агент умер N мин назад»; лампочка жёлтая «агента нет».
2. Та же страница на телефоне и HUD на маке по одному прогону: одинаковая карточка, одинаковый лог, одинаковая плашка; правка CSS в `view.html` после деплоя видна на телефоне.
3. Прогон `stopped`, агент мёртв, терминал закрыт. На телефоне `resume`: сторож поднимает прогон, страница через 30 с показывает «идёт», ответ на старый вопрос, если был, применён.
4. На телефоне `wake` при мёртвом агенте: появляется свежий `claude -p`, аренда живая, он отвечает на вопрос. `wake` при живом агенте: страница показывает отказ, второго процесса нет.
5. Сообщение с телефона во время работы игрока: `tero wait` агента выходит с 7, `tero inbox` показывает текст, игрок сообщение не видел (промпт проверен в ledger), следующий `wait` без сообщений код 7 не даёт.
6. Сообщение при мёртвом агенте: запускается `wake_command` с текстом в размеченном блоке; при пустой `wake_command` страница пишет «агента нет, сообщение ждёт».
7. Хозяин пишет в своей сессии и зовёт инструменты: строки «хозяин» появляются в HUD и на телефоне, результат инструмента с содержимым файла в лог не попал, ключ вида `sk-…` в тексте хозяина замаскирован.
8. Сторож остановлен: страница показывает «машина не на связи», кнопки `wake`/`resume` серые. Без сторожа и без `host` в конфиге всё поведение плана 08 неизменно, существующие тесты зелёные.
9. Фильтр ретранслятора: в D1 нет полей вне белого списка, нет `pid`, строки хозяина не длиннее 300 символов.

# Пульт на телефоне: доводка после разбора 11-12

Статус: три волны критики (Codex Luna) учтены, реализовано и задеплоено 2026-11-12 (aff56900).
Основа: разбор UI/UX 11-12 (светофоры, дубли, молчащие ошибки — уже починено и задеплоено,
версия `cb23c033`). Здесь — следующий слой: страница должна честно говорить, насколько
свежо то, что ты видишь, и не давать промахнуться с ответом.

## Зачем

Хозяин открывает пульт с телефона в двух ситуациях: (1) пришёл пуш «нужен ответ»,
(2) «как там прогон». В обеих сейчас есть ловушки:

- **Немые обрывы.** Если сеть или релей упали, `tick()` пишет `console.warn` и всё.
  На экране остаются старые данные без пометки — выглядит, будто всё в порядке.
- **Свежесть надо высчитывать в уме.** «данные 14:08» — сколько это назад? При открытом
  вопросе опрос раз в 15 с, ответ мог уже уйти с Мака.
- **Промах пальцем необратим.** Кнопки ответа уходят сразу (только «стоп» — через
  `confirm`, нативный диалог, в PWA на iOS неуклюжий).
- **Пуш ведёт в корень.** `sw.js` открывает `/` — первый живой прогон, а не тот, что ждёт ответа;
  уже открытое окно не переиспользуется.
- **Итог закончившегося прогона** приходится собирать из лога глазами.
- **Светофоры:** 23 точки без числа — «где мы» не считывается.
- **Отладка UI** держится на моке во временной папке; баг «точки вылезли на 227 px»
  не поймал бы ни один тест.

## Цели

1. Обрыв связи виден сразу и не путается со «старыми данными».
2. Возраст данных читается без арифметики.
3. Ответ можно отменить в первые секунды; `confirm` больше не нужен.
4. Нажатие на пуш открывает тот прогон, о котором пуш.
5. У закончившегося прогона — одна строка итога.
6. На светофорах видно «фаза N из M».
7. Мок релея и тест вёрстки живут в репо и запускаются одной командой.

## Не цели

- Лог, сгруппированный по фазам — отдельная задача, трогает HUD на Маке.
- Общая карточка решения для EMPLOYED — после этой доводки, отдельной спекой.
- Изменения протокола tero ↔ релей (state.json, команды).
- Нативное приложение (отложено 11-12).

## Анти-цели (провал, даже если «работает»)

- HUD на Маке изменился заметно для хозяина (кроме счётчика фаз, п. 6).
- Отменённый ответ всё-таки дошёл до tero.
- Плашка «нет связи» мигает при одном медленном запросе.
- Пуш перестал приходить на уже подписанный телефон после деплоя.

## Что делаем

### 0. Загрузка: один поток, честный результат
- `get()` возвращает `{status, body, ok}`; `ok` только для 2xx. Сеть упала (fetch бросил)
  → `{status: 0, ok:false}`.
- `load()` — **single-flight**: идёт загрузка → новый вызов ставит флаг `again` и выходит;
  по окончании, если `again`, загрузка повторяется один раз. Перерисовка применяется
  только из последнего запущенного запроса (номер `seq`).
- Результат загрузки: `ok` (оба запроса 2xx), `unpaired` (**любой 401**: `unpaired` — экран привязки
  как сейчас; прочий 401 — тот же экран с пометкой «ключ не принят, привяжи заново»),
  `fail` (status 0 или ≥500, или не-JSON). При `fail` карточка и низ **не перерисовываются** —
  остаётся последнее удачное состояние.

### 1. «Нет связи»
- Счётчик `fails` подряд идущих `fail`; `lastOkMs` — время последней `ok`-загрузки.
- После **2 неудач подряд** над карточкой плашка `#offline`: «нет связи с релеем · с 14:08»
  (`lastOkMs`); удач ещё не было — «нет связи с релеем». `body.stale` приглушает карточку.
  Первая `ok` убирает. Время до плашки: ≈ 4–8 с при открытом вопросе, ≈ 15–30 с без него — принимаем.
- 4xx кроме 401 — не «нет связи», а ошибка запроса: показывается в плашке тем же местом,
  текстом «релей ответил N» (чтобы не молчать).
- Чистая функция `connText(fails, lastOkMs, now)`.

### 2. Возраст данных
- Источник — `state.updated_at` (возраст **данных**), не время ответа релея (это — связь, п. 1).
- В статусе вместо «данные 14:08» — `<span id="age" data-at="…">обновлено 40 с назад</span>`;
  ≤ 60 с обычный, ≤ 5 мин `.age.warn`, > 5 мин `.age.bad`. «ноут молчит» остаётся.
- Свой `setInterval` 5 с переписывает только `#age` (без запроса).
- Чистые `ageText(sec)`, `ageClass(sec)`.

### 3. Темп опроса
- Цикл `setTimeout` вместо `setInterval`: после каждой загрузки задержка
  **4 с**, если в состоянии открыт вопрос, иначе 15 с. Вкладка скрыта → цикл не крутится,
  `visibilitychange` → немедленная загрузка **со сбросом кэша `/runs`** (`runsAt = 0`), чтобы
  возврат из пуша увидел новый ждущий прогон.
- **Не ломать набор текста.** Если фокус в поле ввода внутри `#pult-top` (ответ или сообщение)
  и открытый вопрос тот же — `#pult-top` в этот тик **не перерисовывается** (карточка и низ — да).
  «Тот же» = совпали `qid+run+machine` **и** текст вопроса и список действий. Заморозка не дольше
  **30 с** подряд: дальше перерисовка всё равно (черновик, фокус и курсор восстанавливаются).
  Пока висит плашка «нет связи», кнопки ответа неактивны (данные могли устареть). Иначе при опросе 4 с iPhone дёргает клавиатуру и курсор.
  Дополнительно `restoreDraft` восстанавливает `selectionStart/End`.
- Немедленная загрузка после успешной отправки **ответа** и **сообщения хозяину**
  (оно попадает в лог). resume/wake — как сейчас (у них свой путь итога).

### 4. Ответ с отменой
- Состояние `pending = {action, text, target, run_id, machine_id, qid, deadline, done:false}`.
  Нажатие: если `pending` уже есть — игнор; иначе кнопки и поле блокируются **сразу**,
  над кнопками полоса ««пропустить фазу» через 5 · отменить».
- Единственный переход `pending → sent | cancelled` (флаг `done` ставится до POST,
  повторный вызов — no-op). Один таймер; перерисовка опроса заново рисует полосу из `pending`
  (как `answerNote`), таймер не перезапускается.
- Отмена: «отменить» → `cancelled`, кнопки снова активны, текст в поле сохранён.
- Автоотмена, если при перерисовке тройка `qid + run_id + machine_id` открытого вопроса
  не совпала с `pending` → «вопрос уже закрыт, ответ не отправлен».
- Вкладка скрыта в момент `deadline` → **не отправляем**, автоотмена с текстом
  «свернул — ответ не отправлен, нажми ещё раз». Никаких фоновых отправок.
- Логика ожидания — чистая машина состояний `pendingStep(pending, event, now)` (события: `tap`, `cancel`,
  `tick`, `hidden`, `state`) → `{pending, send?, note?}`; браузер только исполняет `send`.
- `confirm` для «стоп» убираем **в обоих местах**: inline в `renderQuestion` и в `wire()`; — отсчёт его заменяет (моё решение: нативный диалог в iOS PWA
  неудобен и блокирует страницу).

### 5. Пуш открывает нужный прогон — без смены формата пуша
- Формат пуша **не меняется** (старый sw на телефоне, лимиты, шифрование — не трогаем).
- Выбор прогона в `load()` без `run_id` в адресе: сначала прогон со статусом
  `waiting_human`, затем первый живой (терминальные = `done`, `stopped`, `failed`), затем первый. Пуш почти всегда о вопросе →
  нажатие открывает `/`, и страница сама показывает ждущий прогон.
- `sw.js notificationclick`: сначала ищет открытое окно пульта (`clients.matchAll`) и
  фокусирует его (страница при `visibilitychange` перезагрузит данные); нет окна → `openWindow('/')`.
  Изменение sw обратно совместимо: старый sw продолжит открывать `/`.
- Чистая `pickRun(runs)` — тестируется в node.

### 6. Светофоры: «N/M»
- Рядом с точками счётчик `N/M`: N = `view.phase_index + 1`, M = `view.total_phases`
  (или число секторов). Терминальные: сдан весь план → `23/23`; остановлен → фаза остановки.
- Текущая (жёлтая) точка на телефоне — с кольцом.
- Счётчик есть и на Маке (маленький, `--dim`) — единственное видимое изменение HUD.
- Внутри guard `phasesKey` (ключ включает N/M).

### 7. Итог прогона
- `done/stopped/failed`: одна строка в статусе, напр. «сдано 22 из 23 · долг 1 · остановлен вручную».
- Источник чисел — **только** `view.sectors`: сдано = green, долг = orange, всего = длина.
  Нет секторов → `долг` = `state.debts.length`, «сдано» опускается.
  Причина: `stop_text` (через короткий `humanStop` в pult.js) или `done_text`; для `failed` — «упал».
- Чистая `runSummary(state)`; примеры в тестах: done с долгом, stopped без секторов, failed пустой.

### 8. Мок и тест вёрстки
- `relay/dev/mock.py` (сделано): синтетические состояния, `/__mock/offline?on=1|0`, 422 на skip.
- `tests/hud/test_phone_layout.py` (pytest + playwright, `skip` без chromium): сначала
  `sync-hud.sh` уже прогнан (тест сверяет копию, как `test_pult_copy`), мок на свободном порту,
  токен кладётся `add_init_script` в `localStorage.tero_token` до загрузки, вьюпорт 390×844.
  Ожидания — по селектору с таймаутом ≥ 2 интервала опроса (20 с), не фиксированный sleep.
  Проверки: ничего в `#top` не вылезает за вьюпорт; точки внутри `#phases`; клик по точке
  открывает `#plan`; после `offline=1` и двух опросов видна `#offline`, после `offline=0` — исчезает;
  нажатие ответа → полоса отсчёта → «отменить» → POST не ушёл.

## Тесты (node)
- `connText`: одна неудача → пусто (анти-цель «мигание»), две → плашка, без `lastOkMs` — без времени.
- `ageText/ageClass`, `pickRun` (waiting_human > живой > первый; failed — терминальный), `runSummary`.
- `pendingStep`: двойной тап → один send; cancel до дедлайна → нет send и после tick; hidden на
  дедлайне → нет send; смена вопроса → автоотмена; send ровно один раз на дедлайне.
- Черновик: `restoreDraft` восстанавливает `selectionStart/End`.
- Стоп: оба теста `pult.test.js` про `confirm` переписываются — `confirm` не вызывается.
- HUD (`dom.test.js`): счётчик N/M виден без `teroSource`; меняется при той же структуре секторов
  (ключ `phasesKey`); остальная разметка шапки прежняя.
- `sw.js`: `notificationclick` при открытом окне — `focus`, без окна — `openWindow('/')`;
  `push` с текстовой нагрузкой — уведомление как раньше (формат пуша не меняли).

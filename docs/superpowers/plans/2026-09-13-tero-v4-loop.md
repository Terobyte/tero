# Tero v4 Loop Kernel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the deterministic `src/loop/` kernel from the v4 spec so `tero go` runs player → gate → judge → (tester) → SHIP without regex verdicts.

**Architecture:** New package `src/loop/` sits beside the old batch/coach/ldb stack. Each module owns one job and is tested without mocking sessions. `phase.py` takes explicit `deps`; integration tests use `FakeAgents` plus a real git repo and real pytest. Old modules stay until the kernel and CLI switch work.

**Tech Stack:** Python 3.11+, pytest, jsonschema, subprocess git, existing `src.providers` / `process_guard`.

**Spec:** `docs/superpowers/specs/2026-09-13-tero-v4-design.md`

## Global Constraints

- Canonical roles: player `muse`/`muse-spark-1.3`, judge `codex`/`gpt-5.6-terra`, tester `gemini`/`gemini-3.8-flash`, escalation `claude`/`opus`.
- Live providers only: `muse`, `claude`, `codex`, `gemini`, `opencode`, `cursor`. No `zai`/`kilo` aliases.
- New kernel lives in `src/loop/`. Do not delete old `src/` modules in kernel tasks.
- Verdicts come from JSON schemas + git + test exit codes. No regex verdict parsing.
- JSON from final text is fallback only when the provider has no native schema.
- `max_rounds` default is 15 (phase fuse), not the old duel `max_rounds=3`.
- Unknown provider name on any config layer → start fails with exit 1 (S12).
- Judge must not persist tree changes (S6). Player must not delete checkpoint tests (S11) or rewrite tester files (S7).
- Secrets deny-list before commit (S13): `.env`, `.env.*`, `*.pem`, `*.p12`, `id_rsa`, `id_ed25519`, `credentials.json`, `*secret*`, `*credentials*`.
- Commit messages stay lowercase, no conventional-commit prefix, no AI attribution. Do not commit unless the user asks.
- Tests for the kernel live under `tests/loop/`.
- Add `jsonschema` to `pyproject.toml`; do not remove old deps until the deletion task.

## File map

| File | Responsibility |
|---|---|
| `src/loop/__init__.py` | Package marker |
| `src/loop/schemas.py` | JSON schemas + semantic `validate(role, data, ctx)` |
| `src/loop/plan.py` | Parse plan into phases; atomically mark checkboxes |
| `src/loop/gates.py` | Detect and run tests; pytest fingerprint |
| `src/loop/git.py` | All git ops for a run, including deny-list |
| `src/loop/ledger.py` | jsonl events + artifacts + history |
| `src/loop/prompts.py` | System/user prompts for the three roles |
| `src/loop/agents.py` | Extract JSON, repair once, call provider |
| `src/loop/phase.py` | One-phase loop from spec §3.2 |
| `src/loop/run.py` | Start, phase cycle, stop, exit codes |
| `src/loop/config.py` | v4 `LoopConfig` + known-provider check |
| `tests/loop/*` | Unit + FakeAgents integration |

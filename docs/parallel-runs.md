# Два прогона tero на одной машине

Разбор ночи 2026-10-28: dream (`meta`, ветка `tero/2026-10-28-dream-phase1-plan`) и движок (`meta-world`, worktree того же репо, ветка `tero/tero-engine-phase2`) шли одновременно.

## Что уже изолировано (проверено по коду)

- **Процессы.** `ProcessGuard.snapshot_pids` смотрит только потомков своего tero, `proc_tag.sweep` бьёт только процессы со своим тегом окружения. Гейт одного прогона не убивает игрока другого.
- **Лок прогона** — `<wd>/.tero/run.lock`, у каждого worktree свой.
- **HUD** — `~/.tero/registry/<run_id>.json`, по файлу на прогон.
- **Git.** Ветки разные; одну ветку в двух worktree git не даст выписать. tero не зовёт `git stash` и `git gc`; `reset --hard`/`clean -fd` — только в своём worktree.

## Что мешало и чем закрыто (ветка `night/gates`)

1. **Гейт не гонял тесты вообще.** `test_command` вида `cd engine && npm test` резался `shlex.split` и шёл в `Popen` без шелла → `/usr/bin/cd engine && npm test` (POSIX-обёртка macOS) → код 0, пустой вывод, 70 мс. Все `gate ok` обоих прогонов фиктивные; судья получал «цикл уже прогнал тесты». Закрыто: команда с операторами шелла или `cd` в начале идёт в `sh -c` целиком; `{files}` внутри строки подставляется квотированными словами (`gates._override_argv`, `_expand_files`).
2. **Пустой зелёный гейт выглядел как зелёный.** Закрыто: при коде 0 и пустом выводе факт для судьи говорит «тесты, похоже, не запускались — это блокер» вместо «не перезапускай».
3. **Два набора тестов одновременно.** После п. 1 гейты начнут реально гонять наборы: dream ~280 с на unittest с таймингами (`test_hero_touch_goes_through_fsm` уже флакает под нагрузкой полного набора), движок — vitest + Chromium. Закрыто: хостовый лок `~/.tero/gate.lock` (`fcntl.flock`), один набор за раз; ожидание вне `test_timeout_s`; `TERO_GATE_LOCK=off` отключает, `TERO_GATE_LOCK=<path>` переносит.

## Правила хозяину (не код)

- **Разные worktree, непересекающиеся пути записи.** Движок пишет только `engine/**`, dream — `h0/dream/**`, `DEVLOG.md`, `specs/2026-10-28-dream-*`. План каждого прогона запрещает читать территорию другого (`h0/**`, `app/**` для движка).
- **Платные вызовы** (bench dream, ассеты движка) — по «го» и с потолком у каждого; общего бюджета tero не знает.
- **Лимиты Claude общие.** Две лестницы с opus/sonnet на одном аккаунте делят лимит; `limit_wait` tero ждёт, но два opus-раунда одновременно — вдвое быстрее упор. Ставить opus-ступени прогонов не на одно время, где возможно.
- **`max_debt` = 3 на прогон.** План движка теперь 12 фаз одним прогоном; долг пишется в `specs/tero-engine-phase2-debt.md`, кэп считает записи tero, а не файл.
- **Шип хозяина проверять настоящим прогоном**, не гейтом из ledger, пока прогон начат до `night/gates`: живой tero держит старый `gates.py` в памяти до перезапуска.
- **Модули tero не двигать при живом прогоне**; правки — в отдельном worktree tero, слияние в `main` — когда ни один прогон не жив, затем `tero resume`.

# tero: отказоустойчивость, agy, экзамен судей (будущая работа)

Дата: 2026-10-22, правка после волны 1 критиков (Gemini, GLM). Решения Temirlan. Делать ПОСЛЕ прогонов
«Двора», в отдельной копии (worktree), чтобы не менять правила посреди сравнения. Каждый сбой воспроизвести
тестом red→green. Пометка *(моё)* — решение Claude, его можно оспорить.

## Главный принцип

**Работа исполнителя никогда не выбрасывается.** Сейчас любая остановка фазы делает `rollback`
(`src/loop/git.py:84`, вызовы `phase.py:700`, `:730`) — всё написанное стирается. В «Дворе»
так потеряны: фаза 7 у C1 (код был готов, судья спросил NEEDS_USER), фаза 7 у A1 (27 минут).

## 0. Снимок работы (общий механизм для п.1 и п.2) *(моё, по критике)*

- **Когда:** при каждом выходе исполнителя (успех, таймаут, падение, kill), при входе в судью и перед любым
  откатом. Не только «перед откатом»: иначе судья, упавший без отката, ничего не оставляет.
- **Как:** сантехническими командами, без рабочего индекса: временный `GIT_INDEX_FILE`, `git add` отслеживаемых
  и новых не игнорируемых файлов, `write-tree`, `commit-tree`, `update-ref refs/tero/phase-N-roundK`. Так
  зависший `.git/index.lock` от убитого процесса не мешает. Перед снимком проверить, что PID исполнителя мёртв.
- **Что не попадает:** всё из `.gitignore` и deny-list (`.env`, ключи, `node_modules`, `.tero/`). Тест:
  в ref нет путей из deny-list.
- **Неизменяемость:** судья и `resume` работают ТОЛЬКО с ref (`base..ref`), никогда с живым деревом. Что бы
  ни случилось с деревом между падением и resume, судят тот же код. ref и base пишутся в `state.json` и ledger.
- Рабочее дерево после падения исполнителя не трогаем, пока ref не записан и не проверен (`git cat-file -p`).

## 1. Упал / убит исполнитель → новый исполнитель с сохранением прогресса

- Новый исполнитель стартует в НОВОЙ сессии модели (никакого `--continue` для аварийного восстановления:
  история чужой сессии расходится с диском) и получает в промпте: «часть работы уже сделана, вот `git diff
  base..ref`, продолжай, не переписывай готовое».
- Тесты на сыром аварийном снимке НЕ гоняются до раунда нового исполнителя: недописанный код всегда красный.
- Откат к чистой попытке — только после K_max=2 раундов-продолжений подряд, в которых судья не принял и набор
  замечаний не уменьшился. Снимок остаётся в refs для разбора. Считаются только раунды, дошедшие до судьи.
- Тест на моках: stub-исполнитель убит на середине → в промпте stub-исполнителя №2 лежит diff первого
  (проверяем промпт и `git cat-file -p ref`, а не «результат содержит работу»: LLM вправе переписать).

## 2. Упал / ответил не по схеме судья → работу НЕ дропать

- Ответ не по схеме (в т.ч. от `agy --json-schema`) = сбой судьи, как и таймаут.
- В журнале шаг `judge_pending`: «код в `refs/tero/phase-N-roundK`, нужно ревью». Откат не делается.
- `tero go --resume` продолжает **с судьи**: исполнитель не запускается, судья смотрит ref. Флага «начать с
  судьи» сегодня нет — добавить.
- **Модель судьи в рамках прогона не меняется** (убрано «или другая модель»: противоречило экзамену и
  честности A/B). После 3 сбоев подряд — остановка `judge_pending` с текстом «код готов, не принят, вот ref
  и команда `tero review`», не `stuck`. Сменить судью можно только между прогонами.

## 3. Остальное из плана

- Таймаут по зависанию (`stall_timeout_s`: нет вывода N минут), не по часам. Не применять к провайдерам без
  потока (`agy -p` отдаёт ответ целиком в конце): для них только общий таймаут или `--output-format stream-json`.
- Пауза вместо остановки при сетевой ошибке: 1→2→5→10→60 мин, **потолок**: `max_retries` и общий дедлайн
  2 часа на вызов. Ошибки авторизации и квоты (протухший токен `agy`, лимит) — сразу стоп с понятным текстом,
  не ожидание. Сеть отличать от провайдера по коду возврата CLI.
- `TimeoutError` не называть «провайдер недоступен».
- При `--no-escalation` `NEEDS_USER` не принимать: один переспрос судье, затем один свежий судья; третий
  `NEEDS_USER` → `judge_pending` «нужен человек», без бесконечного цикла.
- Неверный формат `config.yaml` (ключи вне `defaults:`) — предупреждение, не молчаливое игнорирование.

## 4. Провайдер `agy` (Antigravity CLI) вместо `gemini`

- Старый CLI `gemini` мёртв (решение Temirlan). Gemini теперь только через `agy` (`~/.local/bin/agy` v1.4.5,
  вход по подписке Google). Проверено 2026-10-22: `agy -p` отвечает, `agy models` отдаёт список.
- **Модели `agy` сегодня** (из `agy models`): `gemini-3.8-flash-high|medium|low`, `claude-sonnet-4-6`,
  `claude-opus-4-6-thinking`, `gpt-oss-120b-medium`. **Gemini 3.1 Pro в списке нет** — дефолт
  `gemini-3.1-pro-preview` из `gemini.py` не переносить. Дефолт для судьи — `gemini-3.8-flash-high` *(моё)*.
  Через `agy` же доступны Claude Sonnet/Opus 4.6 — кандидаты в судьи по подписке Google.
- Флаги: `--print/-p`, `--model`, `--effort low..max`, `--json-schema`, `--output-format text|json|stream-json`,
  `--print-timeout` (формат `900s`, с единицей!), `--continue`, `--conversation`. `--dangerously-skip-permissions`
  только для исполнителя и тестера; **судья получает режим без записи** *(по критике)*.
- Невалидный JSON при `--json-schema` = сбой судьи (п.2), не тихий retry. `--print-timeout` и `stall_timeout_s`:
  побеждает меньший.
- Pre-flight перед очередью: короткий `agy -p` «ок»; нет токена → стоп с просьбой войти, а не зависание на TTY.
  Параллельные `agy` могут делить файлы профиля — в одном прогоне не более одного вызова `agy` одновременно.
- Старый `gemini`: алиас на `agy` с предупреждением в конфиге (миграция), не молчаливое удаление.
- Тест готовности: `--judge agy:gemini-3.8-flash-high` возвращает валидный вердикт по схеме на stub-диффе.

## 5. Экзамен судей (через `Provider` tero, не ad-hoc скрипт) *(по критике)*

- Кандидаты: `agy` (Gemini 3.8 Flash, Claude Sonnet 4.6), `claude` (Sonnet), `codex`, `opencode` (GLM 5.3
  flash, Muse). Идут через те же классы `Provider`, чтобы мерить судью, а не обёртку.
- Два слоя: (1) адаптер — каждый CLI возвращает валидный вердикт на тривиальном диффе; (2) качество.
- Набор: 25–30 диффов (явные баги, тонкие логические, чистые), часть вне «Двора» (holdout). Метки истины —
  два независимых прохода, расхождения разбирает человек. Порог годности фиксируется ДО замеров.
- Мерим: найденные баги, ложные отклонения, ответы не по схеме, время.
- Правило: судья из другой семьи, чем исполнитель. Судью в живом прогоне не менять.

## 6. Стыки с HUD и пультом

- `state.json` получает: `status: judge_pending`, `snapshot_ref`, `base`, причину. HUD показывает «⏸ код ждёт
  ревью» и путь ref, не ❓ и не «упал».
- В пульте `judge_pending` — точка решения: «позвать судью снова / принять вручную / отклонить».
- Порядок работ в сводной спеке: раунд 0 HUD → ядро пульта (state.json, пульс) → отказоустойчивость (эта
  спека) → ретранслятор и телефон.

## Критерии готовности

- Тест: stub-исполнитель убит на середине → `git cat-file -p <ref>` содержит его diff, второй stub получает
  этот diff в промпте.
- Тест: stub-судья вернул мусор → ref есть, дерево нетронуто, `resume` запускает только судью на этом ref.
- Тест: три мусорных ответа судьи подряд → остановка `judge_pending`, не `stuck`.
- Тест на КАЖДЫЙ пункт п.3 (stall, потолок паузы, auth-ошибка без ожидания, `TimeoutError`, `NEEDS_USER` с
  циклом, предупреждение о конфиге) на stub-провайдерах; настоящих LLM в тестах нет.
- Тест: в ref нет путей из deny-list; зависший `index.lock` не мешает снимку.
- Оговорка: `kill -9` самого tero и потеря питания ref не гарантируют; гарантия — для перехватываемых
  сигналов, исключений и смерти дочернего процесса исполнителя.

## 7. Автокомпакт и принудительный компакт (по просьбе Temirlan, 2026-10-22)

**Факты (проверено 2026-10-22):** tero сегодня не держит сессий вообще: каждый вызов роли — новый процесс CLI
(`grep session|continue` в `src/providers/*` пусто). Значит «сессия» = один долгий вызов игрока или судьи, и контекст
растёт внутри него. `claude` имеет `--autocompact <auto|100k–1M>`. `opencode run` имеет `-s/--session`, `--fork`,
`--attach <server>`; флага compact в `run` нет. У `agy` флагов compact/context не нашлось.

- **Автокомпакт** = настройка роли в конфиге: `compact: {auto: true, at_tokens: N}`. Провайдер `claude` — пробрасываем
  `--autocompact N`. Остальные провайдеры — только если у CLI есть механизм; если нет, tero сам ведёт счётчик контекста
  по потоку событий (`stream.jsonl`, см. пульт) и при пороге делает «мягкую смену сессии» (ниже).
- **Принудительный компакт** = команда `tero compact [--role player|judge]` и кнопка в HUD/пульте. Работает по
  `state.json` (владелец прогона читает флаг `compact_requested`).
- **Механика, одна для всех провайдеров («мягкая смена сессии»):** по порогу или по команде tero завершает вызов
  на границе шага, делает снимок работы (п.0), и стартует НОВЫЙ вызов роли с коротким брифом: контракт + `git diff
  base..ref` + список сделанного (ведёт tero из ledger) + «продолжай». Это тот же путь, что новый исполнитель из п.1,
  поэтому ничего нового для устойчивости не нужно. Нативный compact провайдера (если есть) — оптимизация поверх.
- **Судья:** компактить нечего, пока вердикт не выдан; для судьи порог = жёсткий лимит на размер диффа в промпте
  (дифф режется по файлам, длинный идёт в несколько проходов) и принудительный compact = перезапуск судьи на том же ref.
- **Честность A/B:** включать только между прогонами; значение порога пишется в ledger прогона.
- **Не ломать:** compact не должен терять замечания судьи (они идут в бриф дословно) и не считается раундом для K_max.
- **Тесты на stub-провайдерах:** (1) поток превысил порог → stub №2 получил бриф с diff; (2) `tero compact` во время
  вызова → смена на границе шага, ref записан; (3) замечания судьи дословно в брифе; (4) раунд-счётчик не вырос;
  (5) для `claude` в argv есть `--autocompact N`.
- **Открытый вопрос (нужен замер в T0):** умеет ли `opencode` (Muse, GLM) нативный compact через `--attach`/server API.
  Если нет, остаётся только мягкая смена сессии.
